# Review notes

- fixed: Duplicate-request race in `XttvApi` (in-flight slot released before the cache write). The owner now caches first and a new owner re-checks the cache; a 40-round multi-threaded test covers it.
- fixed: A stale entry served after a failed refresh was retried on every read. It now backs off for at most a minute, with a test.
- fixed: No logging of refresh failures (CLAUDE.md §14). Kermit logs the URL without its query string.
- fixed: Unused `koin-core` dependency in `:core:xttv`.
- accepted: De-duplication lives in `XttvApi`, not the client factory; ADR-0007 and the spec were updated to match.
- deferred: Recorded-XML harness in `commonTest` resources. Ticket 02 adds the first real mapper and the first recorded XML.
- deferred: Real `User-Agent` supplier (app name and version in `AppConfig`). Ticket 02 wires the client into DI.
- deferred: `DataUnavailable` in `:domain:club` is awkward for `:domain:player`. Move it when ticket 09 needs it there.
- deferred: An `XttvEndpoint<T>` type for url, ttl and serializer, and a serializer-per-URL guard on the cache. Revisit when the second repository repeats the triple.
- deferred: Possibly timing-dependent concurrency-cap test, and no test for the owner-cancelled take-over path.
- fixed: `dev`, `beta` and `prod` debug builds lost the fake directory when only Associations came from XTTV. Debug builds bind the fake again and `initKoin` binds XTTV after it, so XTTV wins; each of tickets 03-06 and 09 shrinks the fake. On iOS, `Deb` and `Dev` bind the fake.
- fixed: No test of the per-environment binding. `RepositoryModulesTest` covers `deb` (nothing bound), the other environments (XTTV) and XTTV taking precedence over a fake. This also removed the unused `directoryModules(environment)` parameter.
- deferred: `deb` flavor with the `release` build type binds nothing, as every release variant did before. Revisit when the last fake binding goes.
- deferred: The `deb` and `dev` decision is made in `initKoin`, the Android debug source set and iOS `KoinHelper`. Collapses when the interim fake bindings are removed.
- deferred: `XttvHostResolver`'s per-Association `hosts` map and a base URL on `Association`. Populated once ticket 10 settles ADR-0008.
- deferred: `xttvHost` is a constant on `AppConfig`, not derived from the environment. Fine while every environment reads production XTTV.
- accepted: `appVersion` in `AppConfig` and `KoinHelper.start`. Needed for the `User-Agent` the previous review deferred to this ticket.
- fixed: Temporary lineup bridge in `FakeDirectoryModule` was a narrative comment; now a `// TODO:` (§16.5).
- deferred: `XttvEndpoint<T>` type for the repeated endpoint, TTL and serializer triple (now four call sites), and bundling `(api, hosts)` into one type.
- deferred: `XttvHostResolver.defaultHost` is public and callers build URLs from it. Revisit with the resolver once ticket 10 settles ADR-0008.
- deferred: `LineupSource` is nullable on `XttvTeamRepository` (unbound means none); `clubs` could be named `clubRepository`. Both go away when ticket 09 serves lineups.
- deferred: `:core:fake-directory` depends on `:core:xttv` for `LineupSource`; record in an ADR if it outlives ticket 09. Release builds return empty lineups, so ticket 04's "still returns the fake data" holds for debug builds only.
- deferred: `getTeams` goes through `getClub` (up to two extra requests, and fails with `DataUnavailable` if the Club lookup fails even when Teams are cached).
- deferred: `getTeam` and the Club list use the default host; a Club or Team outside it returns `null`. Known limit of ADR-0008 until ticket 10.
- fixed: Club and Team repository tests had no stale-on-failure case; both now cover it through the repository.
- deferred: `getClub` assumes the list and details schemas are identical. Settles with the recorded XML in ticket 10.
- fixed: Fixture, League, Club and Team tests shared a copy-pasted `MockEngine` harness; they now use `FakeXttv`.
- fixed: Naming nits (`homeMatchesWon`, `XTTV_TIME_ZONE`, `assertTrue(none { })`).
- deferred: `getFixtures` picks its host through `getTeam` then `getClub`; same shape as the `getTeams` chain above, and a failed Club lookup throws `DataUnavailable` even when the games are cached.
- deferred: Fixtures use the Club's Association host while League and standings use the default host, so the two can diverge for a non-default Association (ADR-0008). Settle with ticket 10.
- fixed: A Team with a blank `leagueId` (and a blank League id for standings) now returns an empty list without a request.
- deferred: Ticket 05 reads "club and league game data" but only league games are used; no club-level games call.
- deferred: DST tests miss the ambiguous 02:xx hour and the nonexistent spring-forward hour; `toInstant` picks an offset silently.
- fixed: A Game with an unreadable date logs a Kermit warning. Fixing the real date format is still ticket 10.
- deferred: Fixtures are sorted by start time though no ticket asks for it; the Fixture and League tests have no stale-on-failure case (covered in `XttvApiTest`).
- deferred: The fake still binds Fixtures and League; harmless because XTTV wins in `initKoin`. Shrinks when the fake is removed.
